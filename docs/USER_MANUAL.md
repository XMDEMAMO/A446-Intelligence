# A446 Intelligence 用户手册

适用版本：v0.4.0 本地协作原型
适用对象：普通使用者、演示人员、项目维护者

## 1. 系统现在怎样工作

一个用户任务对应一个 Agent 群聊，群内包含该任务的所有内部步骤：

```text
你提出目标
  -> 规划 Agent 拆分并指派
  -> 执行 Agent 提交任务简报 + 完整成果
  -> 审核 Agent 审核完整成果
  -> 规划 Agent 只接收通过审核的简报，并决定是否继续
```

三个角色互不越界：规划 Agent 不执行、不审核；执行 Agent 不自行批准成果；审核 Agent 不重新规划。每个角色只收到当前工作必要的内容。

如果执行 Agent 发现前面的结论有错，它会把上游错误报告交给审核 Agent：

- 审核认可：生成纠错简报，规划 Agent 重新安排。
- 审核不认可：执行 Agent 继续原任务。
- 普通成果不通过：退回原执行 Agent 修改。
- 连续多次不通过或缺少关键决定：请求人工介入。

## 2. 页面说明

### 左侧：任务群聊

- 每一项就是一个完整任务，不是一个设备或一个模型。
- 状态分为进行中、已完成、异常和需人工。
- 点击任务可切换到对应群聊。
- “新建协作任务”会新建一个任务和一个群聊。

### 中间：群聊与成果

- 顶部横条显示规划、执行、审核等内部步骤。
- 每个 Agent 在群里发布任务简报。
- 执行 Agent 的完整成果显示为附件，点击即可展开。
- 每次模型调用下面显示实际返回的输入、输出和总 Token；官方结果不含 Token 时不显示。
- `@Agent` 用于让人看清消息关系和进行提醒，本身不会批准、驳回或重新指派任务。

### 右侧：参与者、账号和额度

- “参与 Agent”同时显示 Agent ID、角色、设备和模型。
- 资源行区分“可用、不可用、未知、陈旧”；陈旧表示本次刷新失败但仍保留最后一次可信结果，不等于 Worker 离线。
- “账号与额度”按本地登录账号汇总多个 Agent 的 Token，而不是把每个模型当成一个账号。
- 一个账号可配置多个模型；Hub 每次任务动态选择，不在流程中写死。
- 有可信客户端快照时显示额度窗口、已用比例和重置时间。
- 客户端没有机器可读额度时显示“未知”，不会用 Token 数估算官方额度。

## 3. 创建任务

点击“新建协作任务”，填写：

1. 任务名称：群聊名称。
2. 目标：最终需要解决的问题。
3. 验收标准：每行一项，必须能判断是否完成。
4. 规划 Agent：通常选“自动选择”。
5. 审核 Agent：通常选“自动选择”。
6. 模型偏好：通常留空，让 Hub 根据能力、负载和额度选择。
7. 审核重试次数：成果连续不通过时允许退回修改的次数。

任务创建后，规划 Agent 会决定执行任务的负责人。规划 Agent 不应把同一个成果交给多个执行 Agent；一个成果只有一个明确负责人。

## 4. 人工介入

当任务顶部或输入区出现“需要你的决定”时：

1. 阅读 Agent 提出的具体问题。
2. 工作流问题可输入补充信息并提交回复；任务重试或审批请求可批准或拒绝，并可附带原因。
3. 提交后等待状态刷新。同一个请求只能处理一次；重复页面或并发点击会收到冲突提示。

人工请求会在服务器重启后保留。人工决定会从请求记录的角色、阶段、父任务和模型会话范围继续，不会无条件从根任务重跑。普通群聊消息只是旁注，不代替这个操作。

QQ 机器人尚未接入；当前人工介入只在网页内完成。

## 5. 设备、账号、Agent 和模型

这四个概念必须分开：

| 对象 | 含义 | 示例 |
| --- | --- | --- |
| 设备 | 一台物理电脑 | `laptop-01` |
| 账号 | 该设备本地登录的服务账号 | `gpt-plus-01` |
| Agent | 一个有独立角色、工作区和会话的执行单元 | `laptop-01-executor-01` |
| 模型 | 账号当前可调用的一项模型能力 | 配置中的真实模型 ID |

同一设备、同一账号可以运行多个 Agent；一个 Agent 也可以在账号允许的模型清单中动态选择。模型不是一个独立登录授权。

## 7. 真实 Worker

真实 Codex 或 Antigravity Worker 需要：

- 本机已安装对应官方 CLI，并通过官方方式登录。
- 每个逻辑 Agent 有唯一的 `agentId`、`stateFile` 和 `workspace`。
- 同一台设备上的 Agent 使用相同 `deviceId`。
- 同一登录账号下的 Agent 使用相同的非敏感账号标识。
- `models` 只列出该账号实际可用的模型。
- 远端 Hub 提供 WSS 地址和独立 Token。

不要把密码、Cookie、浏览器资料、验证码或模型账号凭据放进配置、群聊或 Hub。真实模型测试会消耗账号额度，默认测试不会运行。

## 8. Token 与额度的区别

- Token 统计来自每次模型调用的机器可读结果，可以累计到任务、Agent 和账号。
- 官方额度是账号的时间窗口或套餐限制，只能读取客户端真实提供的数据。
- Token 不能可靠换算成 Plus 或 AI Pro 的剩余额度。
- 限流/耗尽错误只能用于标记粗粒度状态，不能反推出精确百分比。
- 探针刷新失败时保留最后可信额度并标记“陈旧”；从未取得可信快照时仍显示“未知”。

如果官方客户端有可稳定调用的机器可读接口，可由设备所有者配置本地额度读取器。读取器只返回用量 JSON，不得读取或上传登录凭据。

## 9. 验证与排错

一次完成所有 Mock 测试：

```powershell
cd "C:\path\to\A446-Intelligence"
.\scripts\check-all.ps1
```

检查内容包括角色闭环、最小上下文、上游错误裁定、动态模型选择、资源刷新与陈旧降级、人工介入单次恢复、Token/额度解析、Worker 通信、暂停/恢复、审批、取消、网页检查和生产构建。

常见问题：

- 一直排队：没有在线且角色/能力/模型匹配的 Agent，或候选 Agent 已暂停。
- 额度未知：客户端没有提供机器可读快照，不是系统自动判定为零。
- 没有成果附件：执行结果没有结构化 `fullResult`，或任务被策略拒绝。
- 显示演示模式：本地 Hub 未启动或 8787 端口不可访问。
- 权限被拒绝：修改任务范围或由设备所有者明确调整本地策略，不要关闭安全检查。

## 10. 当前边界

- 本地 Mock Hub 用于开发；正式 Server Hub alpha 使用 PostgreSQL、独立身份、Artifact Store 和可靠租约，但仍是单进程，不具备多副本高可用或多租户 RBAC。
- 群聊消息暂存在 Hub 内存中，Hub 重启后不会保留。
- 跨设备成果存储和下载服务尚未实现；当前附件正文来自任务回传，文件清单仍指向 Worker 本地工作区。
- QQ 群机器人按当前决定暂不实现。
