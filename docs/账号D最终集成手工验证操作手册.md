# 账号 D 最终集成手工验证操作手册

适用范围：A446 Intelligence v0.5 最终集成前，由账号 D 完成必须依赖真实设备、真实账号和真实网络环境的手工验证。

本文只说明账号 D 需要亲自完成的部分。服务器部署、数据库迁移、备份恢复、代码合并和自动化测试由最终集成人负责，不在本文重复说明。

## 一、验证原则

预发布服务器上已经完成的测试不需要机械重做。满足以下全部条件时，可以复用原有证据：

1. 原证据记录了测试时间、测试环境、对应的 Git 提交和实际结果。
2. 最终集成后，与该测试有关的代码和配置没有变化。
3. 原证据仍可访问，能够确认任务、Agent、附件或日志确实存在。
4. 原测试使用的是真实设备和真实账号，而不是 Mock Worker。

只要有一项不满足，就不能直接写“已通过”，应重新验证对应项目。

无论复用了多少旧证据，最终集成版本都至少要完成一次真实的双设备最小回归。

## 二、账号 D 与最终集成人的职责边界

### 账号 D 必须亲自完成

- 在账号 D 所在设备上确认真实 Provider 仍处于登录状态。
- 确认该设备能够看到预期模型；如界面提供额度信息，同时记录额度快照。
- 使用该设备的独立 Worker 身份连接最终预发布服务器。
- 完成一次真实双设备协作任务，并核对任务流转、审核结论和成果附件。
- 在相关代码发生变化时，补做 Worker 重连、返工或人工介入验证。
- 保存不含密码、Token、Cookie 的结果证据，并把结论交给最终集成人。

### 最终集成人负责

- 合并分支并给出最终候选版本的完整 Git 提交号。
- 部署最终候选版本。
- 执行自动化发布检查、PostgreSQL 测试、备份恢复和版本回滚。
- 提供账号 D 的一次性 Worker 凭据或已经配置好的启动方式。
- 汇总全部验证证据并作出最终发布决定。

最终集成人可以查看账号 D 的证据，但不能用自己的设备或 Mock Worker 代替账号 D 的真实设备和真实账号验证。

## 三、开始前需要拿到的信息

开始前，向最终集成人确认以下内容：

- [ ] 最终候选版本完整 Git 提交号。
- [ ] 预发布访问地址。
- [ ] 本次合并后发生变化的模块清单。
- [ ] 账号 D 对应的 `agentId`、`deviceId` 和 Worker 配置文件位置。
- [ ] Worker 凭据已经安全放入本机环境，或由最终集成人现场提供一次性凭据。
- [ ] 本次真实调用已经获得人工授权，因为它会消耗 Codex 或 Antigravity/Gemini 额度。
- [ ] 证据保存位置已经确定。

不要把管理员密码、Worker Token、Cookie、数据库连接串或第三方账号凭据写进仓库、任务群聊、截图或验证报告。

### 局域网优先验证说明

本轮可以先在两台设备组成的受信局域网完成组合验证，再转到正式预发布环境：

- 设备 1：运行 Hub、Web、Codex 规划 Agent 和 Codex 执行 Agent。
- 设备 2：运行 Antigravity/Gemini 审核 Agent。
- 必须使用 A、C、B、D 已按规定顺序合并后的本地组合版本，不能用任一单独功能分支代替。
- 当前私有局域网启动入口是仓库根目录的 `START-A446-PRIVATE-LAN.bat`。设备 1 选择服务器，设备 2 选择 Gemini Worker。
- 启动器当前默认服务器地址是 `192.168.137.1`。只有设备 1 实际持有该地址时才能直接使用；换用普通路由器后，应先按实际固定地址调整配置和启动参数。
- 局域网中的 `http://` 和 `ws://` 结果只能证明双设备协作、任务流转和附件逻辑可用，不能替代正式环境的 HTTPS、WSS、Caddy 或安全 Cookie 验证。
- 可以先用 Mock 流程检查界面和连接。启动真实 Codex 或 Antigravity 任务前，仍须取得本次人工授权并记录额度快照。

局域网验证至少保存组合提交号、两台设备的 Agent ID、任务 ID、Attempt ID、使用模型、耗时、Token、审核结论和成果 SHA-256。通过后，正式预发布阶段只需补做局域网无法证明的 PostgreSQL、HTTPS/WSS、systemd、备份恢复和发布门禁。

## 四、判断哪些项目需要重测

| 最终集成后的变化 | 账号 D 的处理 |
| --- | --- |
| 仅修改文档，运行代码和配置没有变化 | 复用原证据，再做一次双设备最小回归 |
| 修改 Provider 适配器、模型发现或额度采集 | 重测登录状态、模型列表、额度显示和一次真实调用 |
| 修改 Worker 协议、认证、心跳、重连或任务租约 | 重测上线、断线重连和任务恢复 |
| 修改调度、角色流转、审核或返工逻辑 | 重测完整协作流程，并增加一次驳回返工 |
| 修改 Artifact 上传、下载或校验 | 重测成果附件上传、下载和 SHA-256 一致性 |
| 修改 Web 登录、任务创建或在线状态显示 | 重测浏览器登录、建任务、在线状态和退出登录 |
| 修改域名、证书、Caddy、端口或网络策略 | 重测 HTTPS、WSS 和 Worker 远程连接 |
| 修改人工介入流程 | 重测等待人工、处理一次以及重复处理保护 |
| 无法确认是否影响上述模块 | 按“有影响”处理并重测对应项目 |

数据库迁移、备份恢复和版本回滚即使需要重测，也仍由最终集成人执行；账号 D 只接收结果，不操作生产或预发布数据库。

## 五、操作步骤

### 第 1 步：建立本次验证记录

复制仓库中的 `docs/V0.5_RELEASE_EVIDENCE.example.json` 到仓库外的安全目录，文件名可使用：

```text
v0.5-最终集成验证证据-YYYYMMDD.json
```

填写：

- `baseSha`：约定的共享基线提交。
- `releaseHead`：本次实际部署的最终候选版本完整提交号。

本次没有亲自执行的自动化、数据库和回滚项目由最终集成人填写。账号 D 主要提供 `workerRestart`、`httpsWss` 和 `realMultiDevice` 的证据。

### 第 2 步：确认当前部署版本

让最终集成人提供服务器当前部署的完整提交号，并与 `releaseHead` 对比。

- 两者完全一致：继续。
- 不一致或无法确认：停止验证，不要把结果记到该候选版本名下。

### 第 3 步：检查账号 D 的设备环境

在账号 D 的设备上确认：

- [ ] 能正常访问预发布网页。
- [ ] 系统日期和时间正确。
- [ ] Provider 客户端或 CLI 已登录。
- [ ] 能看到预期的可用模型。
- [ ] 若客户端提供额度页面，记录调用前的额度百分比和时间。
- [ ] Worker 配置中的服务器地址为最终预发布地址，且使用 `wss://`。
- [ ] `agentId`、`deviceId`、工作区和状态文件属于本设备，没有复制其他设备的身份。

额度无法读取时，记录“客户端未提供可读取快照”，不要自行估算百分比。

### 第 4 步：启动账号 D 的 Worker

优先使用项目提供的启动入口。如果需要直接运行 Worker，使用最终集成人指定的配置文件：

```powershell
cd <A446 项目目录>\apps\agent-hub
node src\worker-cli.mjs --config config\<账号D配置文件>.json
```

检查结果：

- Worker 没有出现认证失败、身份不匹配或重复连接错误。
- Web 页面中该 Agent 显示在线。
- 页面显示的设备、账号/Provider、Agent 角色和模型信息符合实际情况。

如果失败，记录发生时间、Agent ID 和错误摘要；不要截图或复制包含 Token 的完整环境变量。

### 第 5 步：执行双设备最小回归

本阶段目前只有两台设备。可以在设备 1 上运行规划/执行 Agent，在设备 2 上运行审核 Agent；同一物理设备可以承载多个 Agent，但每个 Agent 必须使用独立身份、状态文件和工作区。

创建一个小型、可核对且会产生附件的真实任务。建议任务内容：

```text
任务名称：最终集成双设备回归

目标：生成一份包含当前日期、两台设备 Agent 名称和三条验证结论的 Markdown 报告。

验收标准：
1. 报告包含指定内容；
2. 执行 Agent 提交任务简报和完整成果附件；
3. 审核 Agent 下载并检查附件后给出明确结论；
4. 规划 Agent 最终只接收审核结论和必要简报。
```

观察并记录：

- [ ] 任务被分配给界面中选定的执行 Agent，没有被静默换给其他 Agent。
- [ ] 执行 Agent 收到的是任务指令和必要上下文，而不是整个群聊历史。
- [ ] 执行 Agent 同时提交任务简报和完整成果附件。
- [ ] 审核 Agent 能下载完整成果，并给出通过或驳回结论。
- [ ] 附件名称、大小和 SHA-256 在上传端与下载端一致。
- [ ] 规划 Agent 收到审核结论和必要简报，没有重复读取完整成果。
- [ ] Web 群聊能够清楚区分不同 Agent 的消息、附件和状态。
- [ ] 任务最终状态正确，没有被显示为异常或永久等待。

保存以下证据：任务 ID、Attempt ID、参与 Agent、开始和结束时间、所用模型、最终状态、审核结论、附件 ID 与 SHA-256。

不要在证据中保存完整提示词、账号隐私或任何认证信息。

### 第 6 步：按变化范围补充测试

#### A. Worker 重连测试

仅在 Worker 通信、服务管理或网络配置发生变化时执行：

1. 确认 Worker 当前在线。
2. 正常停止账号 D 的 Worker。
3. 确认 Web 在合理时间内显示离线。
4. 重新启动 Worker。
5. 确认使用同一 Agent 身份重新上线，未产生幽灵 Worker 或重复身份。
6. 再提交一个小任务，确认新任务可以正常领取。

如需验证运行中任务恢复，应使用专门的可丢弃任务，不要拿重要任务做故障演练。

#### B. 驳回返工测试

仅在调度、审核或返工逻辑发生变化时执行：

1. 创建一个验收标准明确的任务。
2. 让执行 Agent 有意漏掉其中一项非危险要求。
3. 审核 Agent 应给出驳回理由。
4. 执行 Agent 根据意见提交新版本成果。
5. 审核 Agent 再次审核并通过。
6. 确认规划 Agent 只收到必要的问题简报、返工安排和最终结论。

#### C. 执行 Agent 发现前序错误

仅在问题上报链路发生变化时执行：

1. 执行 Agent 发现前序信息错误后，不自行改变任务目标。
2. 执行 Agent 向审核 Agent 提交问题报告。
3. 审核 Agent 确认问题是否成立。
4. 审核 Agent 认可后生成问题简报给规划 Agent。
5. 规划 Agent 重新安排任务。

#### D. 人工介入测试

仅在人工介入流程发生变化时执行：

1. 触发一个需要人工决定的可丢弃任务。
2. 确认页面显示“等待人工”，而不是“异常”。
3. 人工只处理一次。
4. 确认重复处理被拒绝，原任务按决定继续或结束。

QQ 机器人尚未接入时，直接在 Web 页面完成人工处理即可。

### 第 7 步：验证 HTTPS 与 WSS

当域名、证书、反向代理或网络配置发生变化时执行：

- [ ] 浏览器通过正式 `https://` 地址打开，没有证书警告。
- [ ] 登录后页面显示 Hub 已连接。
- [ ] 账号 D 的远程 Worker 能通过 `wss://` 上线。
- [ ] 页面刷新和重新登录后仍可恢复正常连接。
- [ ] 页面、API 和 Worker 使用同一个预发布域名，没有退回明文 HTTP/WS。

账号 D 只验证外部实际效果；Caddy 配置、证书续期和服务器端口由最终集成人处理。

### 第 8 步：记录调用后的额度与用量

真实任务结束后记录：

- Provider 和模型名称。
- 调用前后时间。
- 系统能够提供的输入 Token、输出 Token 和总 Token。
- 客户端能够提供的调用前后额度快照。

如果 Provider 只提供百分比而不提供精确 Token，就分别保存百分比和系统侧 Token；不要把两者强行换算成不存在的精确额度消耗。

## 六、通过标准

账号 D 的手工验证可以写“通过”，必须同时满足：

1. 实际部署提交与记录的 `releaseHead` 一致。
2. 账号 D 的真实 Provider 登录有效，预期模型可见。
3. 账号 D 的 Worker 使用独立身份成功上线。
4. 一次真实双设备任务完整通过规划、执行、审核和结果回收。
5. 任务简报与完整成果附件均存在，附件校验一致。
6. 页面没有把正常等待人工、等待审核或 Worker 暂时离线错误显示成系统异常。
7. 所有与本次代码变化相关的补充测试已通过。
8. 证据中包含版本、时间、任务标识和结果，且不含秘密信息。

以下任一情况都应判为“不通过”或“阻塞”，不得写成通过：

- 无法确认服务器实际版本。
- Worker 只能通过关闭认证或使用他人 Token 才能连接。
- 任务被分配给错误 Agent。
- 审核看不到完整成果，或附件哈希不一致。
- 正常等待状态被显示为异常，导致流程无法继续。
- 模型调用成功与否无法确认。
- 证据只是一张启动命令截图，没有实际任务结果。

## 八、结束后的处理

1. 停止仅用于验证的 Worker 或可丢弃任务。
2. 删除本机临时保存的明文一次性 Token。
3. 保留任务、附件和无敏感信息的日志，供最终集成人复核。
4. 将账号 D 的简报和证据位置交给最终集成人。
5. 最终“允许发布”结论仍由最终集成人根据全部自动化、数据库、部署和手工证据统一作出。
