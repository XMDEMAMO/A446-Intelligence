## 二、修复 B 的离线退出行为

当前 `apps/web/src/App.tsx` 在离线页仍以 `!canWrite` 禁用“退出”，而 `submitLogout()` 也要求实时连接。因此用户在 `reconnecting` 或 `offline` 状态下无法清除本地身份并切换账号。

完成要求：

- 清楚区分服务端注销成功与仅清除本地登录状态。离线时不能声称服务端 Session 已撤销。
- 若提供离线本地退出，先明确提示服务端 Session 尚未撤销，再清除本地身份并返回登录界面。
- 网络恢复后不得无提示地把旧 Session 当成用户刚刚重新登录；需要由用户明确发起登录或确认恢复旧 Session 的行为。
- 保持离线禁写：不能为了启用退出而开放创建任务、管理操作或其他服务端写入。
- 覆盖 `offline`、`reconnecting`，以及 `/v1/auth/me` 成功但首次业务快照失败、页面没有实时快照的场景。

新增或更新浏览器 UI 测试，验证离线本地退出提示、身份清除、重新联网后的行为和所有写操作仍被禁用。现有浏览器 E2E 已覆盖管理页面、Worker 一次性 Token、摘要到详情等流程；集成分支必须一起复验。
