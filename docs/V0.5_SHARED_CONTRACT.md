## 1 目的与约束

本文件固定 v0.5 后续并行实施所依赖的字段、接口、状态和错误语义。它是账号 A、B、C、D 的共享契约台账，不表示对应功能已经实现或验收。

执行时必须同时遵守以下约束：

- 当前人类请求和仓库 `AGENTS.md` 优先于本文件。
- `docs/AI_AGENT_MANUAL.md` 与 `apps/agent-hub/AI_IMPLEMENTATION_GUIDE.md` 的安全不变量不得削弱。
- WebSocket 继续使用协议 v1；本轮只增加可选 payload 或控制面字段，不增加 envelope 顶层字段。
- 旧客户端缺少本文件新增字段时必须走明确兼容路径，不得崩溃或改变既有字段含义。
- 本文件没有授权真实模型调用、生产部署、凭据读取或平台限制绕过。

## 2 字段与状态台账

| 领域 | 冻结字段或状态 | 最低语义 | 主要实现账号 |
| --- | --- | --- | --- |
| Workflow 输入 | `executorAgentId?: string \| null` | 缺失或 `null` 表示自动调度；非空值是硬约束 | A、B |
| Workflow 持久化 | `workflow.executorAgentId` | Hub 重启后保留用户选择；旧记录缺失时按 `null` 处理 | A |
| 执行任务 | `requestedAgentId`、`targetAgentId`、`sessionScopeId` | `requestedAgentId` 保存硬约束；`targetAgentId` 保存实际执行者；revision 与安全恢复不得漂移 | A |
| 调度失败 | `schedulingError`、`schedulingErrorCode?`、`schedulingErrorDetails?` | 保留现有可读字符串并增加可选机器码；显式指定不得静默回退 | A、B |
| Web 连接 | `loading`、`live`、`reconnecting`、`offline`、`demo` | 生产连接失败不得进入 `demo`；非 `live` 状态禁止写入 | B |
| Web 同步 | `lastSuccessfulAt?: string \| null` | 仅在一次完整快照成功后更新；陈旧数据必须显式标记 | B |
| 会话状态 | `active`、`completed`、`failed`、`needs_human`、`cancelled` | 全部任务取消且没有失败时为 `cancelled` | A、B |
| Web 用户 | `id`、`username`、`role`、`status`、`createdAt` | `role` 为 `admin \| operator`；HTTP 只能创建 operator | B、C |
| Worker 凭据 | `credentialId`、`agentId`、`deviceId`、`status`、时间字段 | 每个 `agentId` 最多一个 active 凭据；明文 Token 只在创建或轮换响应出现一次 | B、C |

`executorAgentId` 是 `POST /v1/workflows` 的控制面字段，不属于本地 Worker 的 `taskSpec`。Worker 仍通过 `task.assign.agentId`、`task.assign.payload.sessionScopeId` 和 Attempt 信息接收一次具体派发。因此本轮不修改 `task-spec.schema.json`。

## 3 Workflow 与执行者绑定

### 3.1 创建请求

`POST /v1/workflows` 接受：

```json
{
  "title": "任务名称",
  "objective": "任务目标",
  "acceptance": ["可核验标准"],
  "plannerAgentId": null,
  "executorAgentId": null,
  "reviewerAgentId": null,
  "modelPreference": null,
  "reasoningEffort": null,
  "maxReviewCycles": 2
}
```

兼容规则：

- `executorAgentId` 缺失或为 `null` 时，沿用动态选择 Executor 的行为。
- 非空 `executorAgentId` 必须是已知、在线、未暂停且声明 `executor` 角色的 Agent；创建时不满足条件返回 HTTP `409` 和 `EXECUTOR_UNAVAILABLE`，且不创建半成品 Workflow。
- 显式 Executor 的优先级高于 Planner assignment 中的 `targetAgentId`。Planner 输出不同目标时，Hub 使用冻结的 `executorAgentId` 并记录审计事件，不静默改变用户选择。
- 任务已创建后发生满载、可信额度不足或短暂断线时，任务可保持 `queued`，但 `requestedAgentId` 不变，并提供可见的 `schedulingError`；不得改派其他 Agent。
- 自动模式下保持现有动态调度与旧载荷兼容。

### 3.2 revision 与恢复

- 首个执行任务确定实际 `targetAgentId` 后，审核退回产生的 revision 必须复制该 `targetAgentId` 与原 `sessionScopeId`。
- Attempt/Lease 恢复仅可派回 `requestedAgentId` 或原实际执行者；显式绑定不可因重试、Hub 重启或 Worker 重连而漂移。
- 历史 Workflow 缺少 `executorAgentId` 时按自动模式恢复。

### 3.3 调度错误

为兼容已有 Web，`schedulingError` 暂时保留为 `string | null`。新增字段为可选：

```json
{
  "schedulingError": "指定的执行 Agent 当前离线",
  "schedulingErrorCode": "EXECUTOR_UNAVAILABLE",
  "schedulingErrorDetails": {
    "reason": "offline",
    "agentId": "executor-01",
    "observedAt": "2026-09-18T00:00:00.000Z"
  }
}
```

冻结机器码：

- `NO_ELIGIBLE_AGENT`
- `EXECUTOR_UNAVAILABLE`
- `EXECUTOR_PAUSED`
- `EXECUTOR_ROLE_MISMATCH`
- `EXECUTOR_AT_CAPACITY`
- `EXECUTOR_QUOTA_UNAVAILABLE`

## 4 Web 连接与写入边界

- `loading`：尚无成功快照；不得渲染 Demo 或旧业务数据。
- `live`：最近一次完整读取成功；允许按 RBAC 执行写操作。
- `reconnecting`：保留上次成功数据并显示 `lastSuccessfulAt`；禁止写入。
- `offline`：重试窗口结束或明确不可达；禁止写入，不显示绿色在线标识。
- `demo`：只允许由显式 Demo 配置进入；Demo 写入只修改 Demo 状态，不能伪装为生产成功。
- 收到 `401` 后 Web 清空当前 Actor，停止全部受保护业务轮询，只保留登录流程。

## 5 身份与会话接口

### 5.1 登录

`POST /v1/auth/login` 的成功响应保持兼容：

```json
{
  "user": { "id": "uuid", "username": "name", "role": "admin" },
  "csrfToken": "one-session-token",
  "expiresAt": "2026-09-18T12:00:00.000Z"
}
```

登录防护必须同时按来源 IP 和规范化用户名执行。默认只信任 socket 对端地址；只有显式配置受信反向代理后才读取转发地址。失败采用可恢复退避，不使用永久账户锁定。

- 用户名不存在、密码错误和用户被停用均返回相同的 `401 AUTH_INVALID_CREDENTIALS`，避免账户枚举。
- 触发任一限流维度返回 `429 AUTH_RATE_LIMITED`，包含 `Retry-After` 响应头和 `retryAfterMs`。
- 审计可以记录 Actor（成功时）、来源地址摘要、用户名摘要、结果码和时间，不得记录密码、Session Secret、CSRF Secret 或 Worker Token。

### 5.2 当前用户与退出

- `GET /v1/auth/me` 返回 `{ "user": WebUser }`；未认证返回 `401 AUTH_REQUIRED`，且不得先读取其他业务数据。
- `POST /v1/auth/logout` 需要有效 Web Session 与 CSRF，服务端删除当前 Session，再清除 Cookie；成功返回 `{ "ok": true }`。
- 用户被停用或会话被撤销后，已有 Cookie 在下一次请求立即失效。

## 6 管理员用户接口

所有接口仅允许 `admin`，并要求 Session、CSRF 和 Origin 校验。`operator` 返回 `403 FORBIDDEN`。

| 方法与路径 | 请求 | 成功响应 | 关键约束 |
| --- | --- | --- | --- |
| `GET /v1/admin/users` | 无 | `{ users: WebUser[] }` | 不返回密码派生值或 Session Secret |
| `POST /v1/admin/users` | `{ username, password, role?: "operator" }` | `201 { user }` | 缺失 role 按 operator；任何 `admin` 值返回 `403 ADMIN_HTTP_CREATION_FORBIDDEN` |
| `PATCH /v1/admin/users/{userId}` | `{ status: "active" \| "disabled" }` | `{ user }` | 仅允许修改 operator；停用同时撤销其全部 Session |
| `POST /v1/admin/users/{userId}/revoke-sessions` | 无 | `{ ok: true, revokedSessions: number }` | 可撤销任一用户的会话；重复调用幂等 |

`WebUser` 的公开字段为：

```json
{
  "id": "uuid",
  "username": "operator-01",
  "role": "operator",
  "status": "active",
  "createdAt": "2026-09-18T00:00:00.000Z",
  "updatedAt": "2026-09-18T00:00:00.000Z",
  "lastLoginAt": null,
  "activeSessionCount": 0
}
```

`lastLoginAt` 和 `activeSessionCount` 可以为 `null` 或 `0`，但字段含义不得被复用。

## 7 Worker 凭据接口

所有接口仅允许 `admin`。现有路径保持：

| 方法与路径 | 行为 |
| --- | --- |
| `GET /v1/admin/workers` | 返回不含明文 Token 的凭据列表 |
| `POST /v1/admin/workers` | 为新的 `agentId` 创建唯一 active 凭据，响应中一次性返回 `token` |
| `POST /v1/admin/workers/{credentialId}/rotate` | 在同一事务中撤销旧凭据、签发新凭据并断开旧连接，响应中一次性返回新 `token` |
| `DELETE /v1/admin/workers/{credentialId}` | 撤销凭据并断开对应连接；不影响其他 Worker |

约束：

- `agentId` 与 `deviceId` 均为 1 到 128 个字符，不得含控制字符；`agentId` 必须与协议 envelope 限制兼容。
- 同一 `agentId` 已有 active 凭据时，创建返回 `409 ACTIVE_CREDENTIAL_EXISTS`；客户端应使用 rotate，不得自动撤销未知凭据。
- 数据库只保存随机秘密的哈希。任何列表、审计、事件和错误响应都不得返回明文 Token。
- rotate 成功提交后旧 Token 立即认证失败，并关闭使用旧凭据的活动 WebSocket。

## 8 查询与大结果兼容契约

现有全量响应暂时保留为兼容默认。新增查询均为可选、向后兼容：

- `GET /v1/tasks?rootTaskId=UUID&view=summary`：返回任务摘要，不包含 `output`、`submission.fullResult` 或内嵌完整成果内容。
- `GET /v1/tasks/{taskId}`：返回单个完整任务。
- `GET /v1/messages?rootTaskId=UUID&view=summary`：附件保留类型、标签、Task 和 Artifact 引用，但不包含 `full_result` 的 `content`。
- `GET /v1/messages/{messageId}`：返回单条完整消息。

`rootTaskId` 过滤继续是当前会话读取的最低要求。游标分页不在本次冻结范围内；后续增加时必须保持无游标请求的兼容行为。

## 9 HTTP 错误格式

所有新增错误使用以下向后兼容结构；已有客户端仍可只读取 `error`：

```json
{
  "error": "给人阅读的稳定摘要",
  "code": "MACHINE_READABLE_CODE",
  "details": {},
  "retryAfterMs": 1000
}
```

- `error` 必须存在。
- `code` 对新增或修改的关键路径必须存在；不得复用旧代码表达不同语义。
- `details` 只能包含安全、有限且可公开的数据。
- `retryAfterMs` 只在可重试错误需要客户端等待时出现。

冻结错误码：

| HTTP | code | 使用场景 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | 请求字段、JSON 或标识格式无效 |
| 401 | `AUTH_REQUIRED` | 缺少或失效的 Web Session |
| 401 | `AUTH_INVALID_CREDENTIALS` | 登录失败，统一隐藏具体原因 |
| 403 | `FORBIDDEN` | Actor 已认证但角色或对象权限不足 |
| 403 | `CSRF_FAILED` | CSRF 或 Origin 校验失败 |
| 403 | `ADMIN_HTTP_CREATION_FORBIDDEN` | HTTP 尝试创建管理员 |
| 404 | `NOT_FOUND` | 资源不存在或不对 Actor 暴露 |
| 409 | `EXECUTOR_UNAVAILABLE` | 显式 Executor 在创建时不满足硬约束 |
| 409 | `ACTIVE_CREDENTIAL_EXISTS` | 同一 agentId 已有 active 凭据 |
| 409 | `STATE_CONFLICT` | 状态转换或一次性操作冲突 |
| 413 | `PAYLOAD_TOO_LARGE` | 请求或 Artifact 超过配置上限 |
| 429 | `AUTH_RATE_LIMITED` | 登录 IP 或用户名维度触发退避 |
| 503 | `HUB_UNAVAILABLE` | 存储或控制面暂不可用 |

Worker 凭据认证失败统一返回 `401 AUTH_REQUIRED`，不得通过响应区分未知、撤销或秘密错误。

## 10 分支实现边界

- 账号 A：实现 Workflow/Task 执行绑定、revision/恢复不漂移、调度错误与 cancelled 会话状态。
- 账号 B：实现 Web 类型、连接状态、当前用户、系统管理界面、一次性 Token 展示和摘要查询消费。
- 账号 C：实现登录防护、用户与 Worker 管理、数据库约束、部署与恢复；维护本契约和协议文档。
- 账号 D：基于本契约编写跨栈 E2E、PostgreSQL 验收和发布证据，不修改核心实现。

当前身份 HTTP 路由位于账号 A 拥有的 `apps/agent-hub/src/hub.mjs`，数据库身份实现位于账号 C 拥有的 `apps/server-hub/src/identity-service.mjs`。为避免两个分支同时改同一文件，接口边界冻结如下：

- C 在 `IdentityService` 提供兼容的 `login(username, password, context?)`，其中 `context.clientIp` 用于限流；不传 context 时保持旧测试兼容。
- C 提供 `listUsers()`、`setUserStatus(userId, status)`、`revokeUserSessions(userId)`，并让 Worker 创建/轮换方法抛出带 `statusCode` 与 `code` 的安全错误。
- A 只负责在 Hub 核心传入可信解析后的 `clientIp`、挂接本文件冻结的路由，并把安全错误的 `code/details/retryAfterMs/headers` 复制到 HTTP 响应；A 不实现数据库身份逻辑。
- C 的功能分支不得直接编辑 `hub.mjs`；若 A 未提供上述挂接，C 在交接中标记为跨账号阻塞，不通过整文件合并规避。

跨账号需要改变本文件时，先提交最小契约修订，写明兼容影响和测试用例；未经集成账号确认不得让单个功能分支自行改变语义。

## 11 最低契约验收

- 旧 Workflow 请求缺少 `executorAgentId` 时仍可创建并自动调度。
- 显式 Executor 不可用时返回 `409 EXECUTOR_UNAVAILABLE`，不产生半成品 Workflow。
- revision、Lease 恢复和 Hub 重启后显式执行者与 `sessionScopeId` 不漂移。
- 登录限流同时覆盖 IP 与用户名维度，且不会永久锁死合法用户。
- HTTP 无法创建 admin；operator 无法调用任何 `/v1/admin/*` 接口。
- 用户停用和会话撤销立即使已有 Session 失效。
- 同一 `agentId` 只有一个 active 凭据；rotate 后旧 Token 与旧连接立即失效。
- 所有关键错误同时保留 `error` 和机器可读 `code`。
- 摘要查询不携带完整成果，单项详情仍可按需读取。
