## 4. 账号 B：Web 控制台

负责范围：`apps/web/**`。

当前实现的 lint、3 个连接策略单测、生产构建以及现有浏览器 E2E 已通过，但以下事项仍需收尾。

### 4.1 必须修正的事项

1. 处理非实时状态下无法退出的问题。
   - 当前退出按钮在 `reconnecting` 和 `offline` 时被禁用。
   - 当 `/v1/auth/me` 成功、但首次业务快照加载失败时，离线页面只有重试入口，用户无法返回登录界面或切换账号。
   - 必须明确区分“服务端注销成功”和“仅清除本地界面状态”。网络不可用时不得谎称服务端 Session 已撤销。
   - 如果提供本地退出，应明确提示服务端会话尚未撤销，并确保恢复网络后不会无提示地把旧身份伪装成一次新的登录成功。

2. 为真实管理界面补浏览器测试，而不是只从页面内直接调用 API。
   - 管理员创建、停用和启用 operator；
   - 撤销用户 Session；
   - 创建、轮换和撤销 Worker 凭据；
   - 明文 Worker Token 仅在创建或轮换成功后显示一次；
   - Token 不进入 `localStorage`、`sessionStorage`、URL、列表接口或日志；
   - operator 看不到管理入口，并且服务端调用仍返回 `403 FORBIDDEN`。

3. 补充真正的摘要到详情测试。
   - Fixture 在 `view=summary` 时必须移除完整成果正文。
   - 展开完整成果后，页面应调用 `/v1/messages/{messageId}`，并只加载所需单项。
   - 如页面需要任务完整字段，应按需调用 `/v1/tasks/{taskId}`，不得恢复全量轮询。
   - 重复展开不得造成无界重复请求。

## 5. 账号 D：验证、发布门禁与证据

负责范围：`tests/e2e/**`、发布检查脚本和发布证据文档，不修改核心实现。

### 5.1 必须修正的契约夹具

当前测试 Fixture 与冻结契约或 A/C 实际响应存在差异，需要统一：

1. `GET /v1/admin/workers` 使用 `{ credentials: [...] }`，不要只返回 `{ workers: [...] }`。
2. Worker 创建和轮换响应应覆盖 A/C 实际的 `{ credential: { ..., token } }` 形状；列表响应不得包含 `token` 或 `tokenHash`。
3. 已认证但权限不足统一使用 `403 FORBIDDEN`，不要使用 `ADMIN_REQUIRED` 代替冻结机器码。
4. CSRF 或 Origin 校验失败统一使用 `403 CSRF_FAILED`，不要使用 `CSRF_INVALID`。
5. Fixture 必须实现并验证：
   - `GET /v1/tasks?rootTaskId=...&view=summary`；
   - `GET /v1/tasks/{taskId}`；
   - `GET /v1/messages?rootTaskId=...&view=summary`；
   - `GET /v1/messages/{messageId}`。
6. 补齐用户管理 Fixture 和 UI 流程，覆盖用户创建、状态修改、Session 撤销及 operator 越权拒绝。

### 5.2 修正干净检出环境的测试入口

`scripts/check-all.ps1` 当前直接执行 `tests/e2e` 的测试，但干净检出时可能尚未安装锁定的 `playwright-core`。必须让文档和脚本形成可重复流程，例如在明确的依赖安装阶段执行：

```powershell
Set-Location tests/e2e
npm.cmd ci
npm.cmd test
```

不得依赖某台机器上碰巧已有的全局包或旧 `node_modules`。

### 5.3 发布证据要求

- 只有组合分支全部自动检查通过后，才能把发布报告从“进行中”更新为“通过”。
- PostgreSQL、真实浏览器、真实反向代理和部署演练必须区分“已实际执行”和“仅提供脚本”。
- 未执行的 Linux/Caddy/systemd/HTTPS/WSS、备份恢复或多机验证必须明确写为未验证，不能以 Mock 测试代替。
- 证据中记录提交 SHA、执行时间、环境摘要和每个命令的结果，不记录任何秘密。
